# 🔄 Rano IDE 1.0.7 — startup updates, browser downloads and SDK import guidance

> **Correction in 1.0.9:** The earlier archive diagnosis used Xcode.app’s compiler build instead of its product build. A genuine stable archive can contain a differing DTXcodeBuild. See the [product-identity fix](AUDIT-1.0.9.md). The previous reader’s mismatch was not proof that the downloaded product was an RC.

## 📥 Download outside the app

Apple SDK releases now includes **Open Apple downloads in your browser**. It opens the official Apple download search for the currently selected release in the default browser. Users sign in and download the full Xcode .xip there, then return to **Import downloaded Xcode**. The existing embedded download and import options remain available. If browser opening fails, a selectable official URL appears for copying. Release titles are URL encoded; no signed download URL or credentials are supplied to the browser action.

## 🔎 Clear release mismatch

The reported archive identifies itself as Xcode27.1 RC build27A9274 while the selected stable release is27A9275. Rejecting that mismatch before replacement is correct. The importer continues to enforce exact source-build matching for every project. It now reports this expected refusal as a structured result without a Python traceback. The visible message names actual and selected builds, states that installed SDKs were not changed, and directs the user to download the selected release. Generic SDK recovery advice is reserved for other failures. Choosing another source release deliberately remains available, but is not presented as the recovery for an unwanted prerelease archive.

## 🔄 Startup checks for both update sources

Normal application startup performs fresh public GitHub and official Apple release checks, alongside a local installed-SDK identity check. Independent reads run concurrently with bounded network/WSL timeouts. Environment discovery starts after the update prompt completes. Opening another project window does not trigger another startup check; Help has an explicit manual check. Available updates, missing tools, unknown SDK provenance and unavailable/offline checks are distinguished. An unavailable check is not reported as proof that everything is current. Continue permits deferral after the prompt.

Only stable published IDE releases newer than the installed version qualify. The installer filename, official repository/tag asset URL, uploaded state and size are validated. GitHub redirects are restricted to HTTPS GitHub delivery hosts. In-app installer downloads require the exact published size and SHA-256, using the release checksum file and/or GitHub's asset digest; conflicting checksums are rejected. Partial, oversized, truncated, corrupt and non-executable downloads are not exposed as verified installers. The file is hashed again before explicit Run installer. No unattended EXE execution or forced closure of unsaved projects occurs. Cancellation removes the partial download and retains the installed app. Existing unsigned-installer limitations remain; checksums do not constitute publisher code signing.

The live current public release is older than the local build and is correctly not offered as a downgrade. The owner's SDK source provenance is unrecorded, so the live startup UI offers SDK verification without claiming a newer SDK was installed. No private app sources, signing credentials or API keys are sent in these update checks. Future users receive new desktop versions only after verified release assets are published; publishing those assets remains a separate release step.
